# LearnTrack — Build Variants

**Phase:** Phase Group 4 — MCP Setup + Build Variants + Quality Gates  
**Platform:** Android (Gradle with Kotlin DSL)  
**Status:** Pre-scaffold — build files have not yet been created. This document describes the target build configuration that must be implemented during the scaffold phase.  
**Last Updated:** Phase Group 4

---

## 1. Overview

LearnTrack is an Android application built with Gradle (Kotlin DSL). The build system provides two standard build types (`debug` and `release`) and no product flavors for this phase. Product flavors are out of scope unless a multi-environment data source requirement is approved.

All build commands use the Gradle wrapper (`gradlew.bat` on Windows, `gradlew` on macOS/Linux), which must be committed to the repository during the scaffold phase.

---

## 2. Build Types

### 2.1 `debug`

| Property | Value |
|---|---|
| **Purpose** | Local development and automated testing |
| **Debuggable** | `true` |
| **Minification** | `false` (ProGuard/R8 disabled) |
| **Application ID suffix** | `.debug` (e.g., `com.learntrack.debug`) |
| **Signing** | Debug keystore (auto-generated by Android SDK) |
| **Build config `DEBUG`** | `true` |
| **Logging** | Verbose logging enabled via `BuildConfig.DEBUG` |
| **Data source** | `app/src/main/assets/learntrack_topics.json` |

**Build command:**
```powershell
# Windows
.\gradlew.bat assembleDebug

# macOS/Linux
./gradlew assembleDebug
```

**Output artifact:** `app/build/outputs/apk/debug/app-debug.apk`

**When to use:**
- Day-to-day development
- Running automated unit tests and UI tests
- Debugging on a device or emulator
- Pre-push quality gate validation

---

### 2.2 `release`

| Property | Value |
|---|---|
| **Purpose** | Distribution-ready build for production |
| **Debuggable** | `false` |
| **Minification** | `true` (R8 enabled — shrinks and obfuscates code) |
| **Application ID suffix** | None (e.g., `com.learntrack`) |
| **Signing** | Release keystore (supplied via `local.properties` — never committed) |
| **Build config `DEBUG`** | `false` |
| **Logging** | Verbose logging suppressed via `BuildConfig.DEBUG` guard |
| **Data source** | `app/src/main/assets/learntrack_topics.json` |

**Build command (unsigned — for local verification):**
```powershell
# Windows
.\gradlew.bat assembleRelease

# macOS/Linux
./gradlew assembleRelease
```

**Build command (signed — requires keystore configuration in `local.properties`):**
```powershell
# Windows
.\gradlew.bat bundleRelease

# macOS/Linux
./gradlew bundleRelease
```

**Output artifacts:**
- APK: `app/build/outputs/apk/release/app-release.apk` (or `app-release-unsigned.apk` if no signing config)
- AAB: `app/build/outputs/bundle/release/app-release.aab`

**When to use:**
- Building the production APK/AAB for distribution
- Performance testing (minification affects startup time)
- Final release-readiness verification

**Important:** The release keystore must never be committed to the repository. Store signing credentials in `local.properties` (git-ignored) or in CI secrets.

## 3. Gradle Task Reference

| Task | Description | Command |
|---|---|---|
| `assembleDebug` | Build debug APK | `.\gradlew.bat assembleDebug` |
| `assembleRelease` | Build release APK (unsigned if no signing config) | `.\gradlew.bat assembleRelease` |
| `bundleRelease` | Build release AAB for Play Store | `.\gradlew.bat bundleRelease` |
| `testDebugUnitTest` | Run all unit tests against debug variant | `.\gradlew.bat testDebugUnitTest` |
| `testReleaseUnitTest` | Run all unit tests against release variant | `.\gradlew.bat testReleaseUnitTest` |
| `connectedDebugAndroidTest` | Run instrumented/UI tests on connected device | `.\gradlew.bat connectedDebugAndroidTest` |
| `lintDebug` | Run Android Lint against debug variant | `.\gradlew.bat lintDebug` |
| `lintRelease` | Run Android Lint against release variant | `.\gradlew.bat lintRelease` |
| `clean` | Delete all build outputs | `.\gradlew.bat clean` |
| `dependencies` | List all resolved dependencies | `.\gradlew.bat app:dependencies` |

## 4. Product Flavors

**No product flavors are defined for this phase.**

LearnTrack has a single data source (`learntrack_topics.json` bundled in the APK). There is no remote API, staging backend, or multi-environment data source that would justify a product flavor dimension.

If a future requirement introduces a staging vs. production API endpoint, product flavors would be the appropriate mechanism:

```kotlin
// Hypothetical future use — NOT in scope for this phase
flavorDimensions += "environment"
productFlavors {
    create("staging") { dimension = "environment" }
    create("production") { dimension = "environment" }
}
```

## 5. Build Configuration Source

The build system uses Gradle with Kotlin DSL. Key configuration files (to be created during scaffold):

| File | Purpose |
|---|---|
| `build.gradle.kts` (root) | Root build configuration; `buildscript` and plugin declarations |
| `settings.gradle.kts` | Module inclusion (`include(":app")`) and repository declarations |
| `app/build.gradle.kts` | App module build config; compileSdk, minSdk, targetSdk, dependencies |
| `gradle/libs.versions.toml` | Version catalog — all dependency versions pinned exactly |
| `gradle/wrapper/gradle-wrapper.properties` | Gradle wrapper version (pinned, committed) |
| `local.properties` | Local SDK path and signing credentials — **git-ignored, never committed** |

## 6. Test Execution by Build Variant

| Test Type | Command | Variant | Requires Device |
|---|---|---|---|
| Unit tests (debug) | `.\gradlew.bat testDebugUnitTest` | debug | No |
| Unit tests (release) | `.\gradlew.bat testReleaseUnitTest` | release | No |
| UI tests (instrumented) | `.\gradlew.bat connectedDebugAndroidTest` | debug | Yes (emulator or physical) |
| All checks | `.\gradlew.bat check` | debug | No (UI tests excluded by default) |

The pre-push quality gate script (`scripts/check-before-push.ps1`) runs `testDebugUnitTest` and `lintDebug` on the debug variant, which does not require a connected device. UI tests are run separately in CI on an emulator.
