# LearnTrack — Environments

**Phase:** Architecture and Data Design (Phase Group 2)
**Status:** Baseline — pre-scaffold; describes target state. No build system exists yet.
**Last Updated:** Phase Group 2

---

## 1. Overview

LearnTrack is an Android application. The environment model is defined by Android Gradle build types and, when needed, product flavors. No backend, cloud service, or containerized runtime is involved in this phase.

Because no `build.gradle.kts` or source code exists yet, all environment definitions below describe the **target state** that must be implemented during the scaffold phase.

---

## 2. Local Development Environment

### Purpose
Day-to-day development, debugging, and local testing on an Android device or emulator.

### Prerequisites
- Android Studio (latest stable recommended; Electric Eel or newer)
- JDK 17 (bundled with Android Studio or installed separately)
- Android SDK (API level 26+ minimum; API 34 recommended target)
- A connected Android device (API 26+) or AVD (Android Virtual Device)
- `local.properties` file with `sdk.dir` pointing to the local SDK installation

### Build Command
```powershell
.\gradlew assembleDebug
```

### Install and Launch
```powershell
.\gradlew installDebug
```

### Unit Tests
```powershell
.\gradlew testDebugUnitTest
```

### Lint
```powershell
.\gradlew lintDebug
```

### Configuration Source
- `app/build.gradle.kts` — build type `debug`
- `local.properties` — SDK path and any local overrides (git-ignored)
- `app/src/main/assets/learntrack_topics.json` — bundled data asset

### Data Source
- `assets/learntrack_topics.json` read via `AssetManager` at runtime
- No network calls; no external database

### Debug Settings
- `BuildConfig.DEBUG == true`
- `android:debuggable="true"` (set automatically for debug builds)
- Verbose logging enabled via `BuildConfig.DEBUG` guard
- Android Studio debugger and Layout Inspector available

### Secrets
- No API keys or credentials required for the current feature scope
- `local.properties` must never be committed (already in `.gitignore`)

## 3. Build Types

Android Gradle supports build types out of the box. The target configuration for LearnTrack:

### debug (Development)

| Property | Value |
|---|---|
| `buildType` | `debug` |
| `debuggable` | `true` |
| `minifyEnabled` | `false` |
| `shrinkResources` | `false` |
| `applicationIdSuffix` | `.debug` (recommended — allows debug and release installed side-by-side) |
| `versionNameSuffix` | `-debug` |
| `BuildConfig.DEBUG` | `true` |
| Signing | Debug keystore (auto-generated by Android Studio) |
| ProGuard / R8 | Disabled |
| Logging | Full verbosity |

### release (Production)

| Property | Value |
|---|---|
| `buildType` | `release` |
| `debuggable` | `false` |
| `minifyEnabled` | `true` |
| `shrinkResources` | `true` |
| `applicationIdSuffix` | (none) |
| `BuildConfig.DEBUG` | `false` |
| Signing | Release keystore (from `local.properties` — never committed) |
| ProGuard / R8 | Enabled; rules in `proguard-rules.pro` |
| Logging | Verbose log calls stripped by ProGuard/R8 |

**Release signing configuration** (to be added to `app/build.gradle.kts`):

```kotlin
signingConfigs {
    create("release") {
        storeFile = file(properties["KEYSTORE_PATH"] as String)
        storePassword = properties["KEYSTORE_PASSWORD"] as String
        keyAlias = properties["KEY_ALIAS"] as String
        keyPassword = properties["KEY_PASSWORD"] as String
    }
}
```

All four signing properties are read from `local.properties` and never hard-coded.

## 4. Product Flavors

**No product flavors are required for the current phase.**

The app has a single deployment target (Android phones, English, no regional variants). If future phases introduce environment-specific behavior (e.g., a staging vs. production API endpoint), a `dimension "environment"` with `staging` and `production` flavors would be the appropriate mechanism.

For now, build type (debug / release) is sufficient to differentiate development from production builds.

---

## 5. Staging Environment

**Not configured in this phase.**

LearnTrack is a read-only, asset-based application with no backend. There is no staging server, API, or deployment target that would require a staging environment configuration.

If a backend or remote data source is added in a future phase, a staging environment would be defined as:
- A separate product flavor (`staging`) with a different base URL injected via `BuildConfig`
- A separate Firebase project (if Firebase is adopted)
- No staging App Distribution or Play Store track until that phase is approved

---

## 6. Production Environment

**Not deployed in this phase.**

Production deployment requires explicit approval per the scope document. The release build type produces a production-ready APK/AAB, but no distribution to the Play Store or any release channel is automated here.

When production deployment is approved, the release build would be distributed via:
- Google Play Store (internal → closed → open track)
- Or direct APK distribution if Play Store is not required

The CI/CD pipeline (GitHub Actions) would be extended to produce a signed AAB on tag push, but deployment to Play Store is a separate manual approval step.

## 7. Environment Variable Names and Configuration Sources

All environment-sensitive values are sourced from `local.properties` or environment variables in CI. Nothing is hard-coded in committed files.

| Variable | Source | Used in | Purpose |
|---|---|---|---|
| `sdk.dir` | `local.properties` | `local.properties` | Android SDK path (local only) |
| `KEYSTORE_PATH` | `local.properties` / CI secret | `app/build.gradle.kts` | Release signing keystore file path |
| `KEYSTORE_PASSWORD` | `local.properties` / CI secret | `app/build.gradle.kts` | Keystore password |
| `KEY_ALIAS` | `local.properties` / CI secret | `app/build.gradle.kts` | Key alias within keystore |
| `KEY_PASSWORD` | `local.properties` / CI secret | `app/build.gradle.kts` | Key password |

### CI/CD (GitHub Actions)

In GitHub Actions, signing credentials are stored as repository secrets and injected as environment variables into the workflow. The `local.properties` file is generated during the CI run from those secrets — never committed.

## 8. Data Source and Persistence Per Environment

| Environment | Data source | Persistence | Notes |
|---|---|---|---|
| debug | `assets/learntrack_topics.json` | None (read-only) | Same asset as release; no DB |
| release | `assets/learntrack_topics.json` | None (read-only) | Bundled in APK |
| Test (unit) | In-memory `List<Topic>` or test asset | None | No file I/O in pure unit tests |
| Test (instrumented) | Test asset copy via `androidTest/assets/` | None | Injected via test module |
